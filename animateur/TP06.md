## Architecture du lab

Le lab fait dialoguer deux machines :
- `clt-N` héberge le **collector** OpenTelemetry et le backend Jaeger (stack Docker Compose).
- `srv-N` héberge les quatre runtimes applicatifs natifs (Java, Python, .NET, PHP) et leurs **agents** d'auto-instrumentation respectifs.

Le participant travaille exclusivement depuis le terminal web de `clt-N`. Toutes les opérations sur `srv-N` sont menées via SSH sans mot de passe depuis ce terminal.

## Rejeu du 22 novembre 2026 (clt-0 et srv-0)

Le rejeu complet a été déroulé depuis `clt-0` en pilotant `srv-0`.

- **Partie 1 (Backends)** : stack Compose lancée sur `clt-0` (ports 16686 et 4318), copie des sources sur `srv-0:~/tp06`.
- **Partie 2 (Java)** : installation d'OpenJDK 21, téléchargement de l'**agent** Java 2.34.0, compilation de `checkout.java`, démarrage en arrière-plan avec `setsid nohup java -javaagent:...`. Premier appel : `checkout` répond `{"orders":"1 mug","inventory":{"error":"ConnectException"}}` car le service suivant n'est pas encore en ligne. Jaeger enregistre `checkout`.
- **Partie 3 (Python)** : création du venv Python, installation de Flask, requests et OpenTelemetry, exécution de `opentelemetry-bootstrap`, démarrage avec `opentelemetry-instrument`. Deuxième appel : réponse `{"orders":"1 mug","inventory":{"sku":"1 mug","price":{"error":"ConnectionError"}}}` car .NET n'est pas encore démarré. Jaeger enregistre `inventory`.
- **Partie 4 (.NET)** : installation du SDK .NET 10, compilation de `pricing`, extraction de l'auto-instrumentation .NET 1.20.0, démarrage avec `instrument.sh`. Troisième appel : `HttpRequestException` sur l'appel PHP. Jaeger enregistre `pricing`.
- **Partie 5 (PHP)** : installation de PHP 8.3-cli et des outils de compilation, installation PECL de l'extension `opentelemetry-1.1.0`, `composer install` dans `shipping`, démarrage du serveur intégré. Quatrième appel : la chaîne complète répond avec succès (`carrier: colissimo`, `eta_days: 2`). Les cinq services (`checkout`, `inventory`, `pricing`, `shipping`, `jaeger`) sont présents dans Jaeger.
- **Partie 6 (Traces multi-langages)** : 5 requêtes envoyées, extraction des spans de la trace (les 4 spans serveur, les spans client dédoublonnés sous `3 GET`, et le span interne `{closure}` de Slim). Comparaison des attributs de ressource confirmant l'homogénéité du modèle sémantique malgré quatre runtimes et versions de SDK différentes.
- **Cleanup** : arrêt des processus avec `pkill`, purge des paquets sur `srv-0`, arrêt de la stack Compose sur `clt-0`. Tous les ports (8080, 8081, 8082, 8083, 4318, 16686) redeviennent libres.

## Pièges constatés et corrections appliquées

- **Sorties JSON intermédiaires** : aux parties 2 et 3, le lab indiquait précédemment des sorties partielles erronées (stock complet en partie 2 alors qu'inventory n'était pas démarré, `price: null` en partie 3 au lieu de `price: {"error": "ConnectionError"}`). Les sorties ont été corrigées avec les résultats réels du rejeu.
- **Dédoublonnage dans jq** : la commande `unique` en partie 6 regroupe les trois spans client sous une seule ligne `3 GET`. Le texte a été clarifié pour expliciter ce comportement.
- **Attributs de ressource complets** : le bloc d'attributs de la partie 6 affichait une troncature manuelle (`...`). Il affiche désormais la liste exhaustive des attributs de ressource des 4 services telle qu'extraite de Jaeger.
- **Motif de pkill dans le cleanup** : le binaire Java s'exécute comme `java -javaagent:... checkout` et non `checkout.java`. La commande `pkill -f "[c]heckout.java"` ne tuait donc pas le processus Java, qui continuait d'écouter sur le port 8081. Le motif est corrigé en `[j]ava.*checkout`.
- **Avertissements métriques dans les logs Java** : l'**agent** Java active par défaut l'export de métriques vers `/v1/metrics`. Comme le **collector** du lab n'a qu'un pipeline de traces, il renvoie des codes HTTP 404 sur les requêtes de métriques. Ces avertissements dans `/tmp/checkout.log` sont sans incidence sur les traces et disparaissent dès qu'un pipeline de métriques est configuré (sujet des TP suivants).
