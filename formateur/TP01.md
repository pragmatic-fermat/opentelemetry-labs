## Ce qui n'a pas été exécuté

Les commandes du lab sont données à titre indicatif : elles n'ont pas été exécutées lors de la rédaction et sont à contrôler sur de vraies machines. Les points suivants sont à vérifier en priorité lors d'une première passe sur un pod :

- la présence des chemins `/api/traces` de Jaeger 2.23.0, utilisés dans les sorties attendues (l'interface les utilise elle-même, mais ils ne sont pas documentés comme stables) ;
- le provisioning de la source de données Jaeger sur Grafana 13.3.1 ;
- le nombre exact de lignes `Span #` affiché par l'exporter `debug` (dix pour cinq traces de deux spans) ;
- le nom final de la métrique dans Prometheus, qui dépend de l'unité émise par `telemetrygen` ;
- le comportement des instructions OTTL de la partie 5 sur la version 0.165.0 ;
- l'acceptation du fichier `processors.yaml` réduit à `processors: {}` à la partie 2 (le Collector attend les quatre fichiers avant que les processors soient écrits) ;
- la fusion des quatre fichiers passés avec plusieurs options `--config` (les clés de premier niveau sont toutes différentes, donc seule la fusion de base est sollicitée) ;
- l'écriture des fichiers par here-document dans le terminal de code-server (collage de plusieurs lignes indentées).

## Points d'attention

- Aucune étape ne demande d'ouvrir un éditeur : les fichiers sont écrits avec `cat > fichier <<'EOF'`, complétés avec `cat >>` et modifiés avec `sed`. Les erreurs les plus probables sont une indentation perdue au collage et un `EOF` oublié (le terminal affiche alors une invite `>`). Le lab donne les configurations en entier : un participant bloqué peut les recopier depuis l'énoncé.

- Le tag de l'image du Collector est `0.165.0` mais celui de `telemetrygen` est `v0.165.0` (avec le `v`). C'est vérifié dans le registre ghcr.io.
- `telemetrygen` émet un débit de 1 span par seconde et par worker par défaut, et les spans enfants comptent aussi. Le script `tg.sh` impose `--rate 10` pour que les commandes restent rapides.
- Le filtrage supprime ici le span parent et le span enfant, car `telemetrygen` pose les attributs sur les deux. Sur une vraie application, supprimer seulement le span racine laisserait des spans enfants orphelins : c'est un bon point de discussion sur le filtrage par trace (échantillonnage par la queue) plutôt que par span.
- L'ordre des instructions de la partie 5 est le piège le plus fréquent : renommer avant de normaliser donne un nom avec l'identifiant brut.
- Le mot de passe Grafana par défaut est `formation`, et le port 3000 est ouvert sur Internet d'après les conventions. À changer via la variable `GRAFANA_ADMIN_PASSWORD` si l'environnement est exposé à des tiers.
- Jaeger stocke en mémoire (`max_traces` de 100 000 dans sa configuration par défaut) : un redémarrage du conteneur efface tout.

## Pour la discussion

- Dans le README du composant, `queuebatch` est présenté comme le remplaçant du processor `batch`. Les deux sont présents dans la distribution contrib 0.165.0 et `batch` reste en statut beta : ce TP garde `batch` parce qu'il est le plus répandu dans les configurations existantes.
- Les composants du Collector ont un type et un nom d'instance (`otlp_grpc/jaeger`). La distinction revient dans les TP suivants.
- Plusieurs composants ont changé de type : `otlp` est devenu `otlp_grpc` pour l'exporter, `otlphttp` est devenu `otlp_http` et `k8sattributes` est devenu `k8s_attributes`. Les anciens noms restent acceptés comme alias dépréciés dans la version 0.165.0 (champ `deprecated_type` du composant), mais les configurations trouvées sur Internet les utilisent encore beaucoup : les participants peuvent les rencontrer.
